# Architect · 架构选项与取舍（#37）

## A1 数据宿主：Report.Api vs Model.Api
- **候选 R1（选定）Report.Api**：沿用 #36 确立的「唯一只读聚合出口」范式，复用 keyed `IMongoDatabase("arena-dashboard-model")` + `IsAgentSubResolver`，不引用 Model.Api 程序集、零写操作。猎手名解析走运行时 HTTP 读 User.Api（缓存 + 降级）。
- **候选 R2 Model.Api（arena-route）**：复用全部数据与现有 LLM 生成器，但模糊「只读聚合出口」边界，且 Model.Api 有写能力，公开端点放此处风险更高。
- **取舍**：R1 严守 #36 架构纪律，公开只读场景最契合。

## A2 公开鉴权：匿名端点 vs 版主端点
- **候选 R1（选定）匿名**：名人堂是公开页（验收明确「公开页面」），端点不加 `RequireForumModerator`/`Authorize`；前端路由不设 `requiresAuth`。
- **候选 R2 版主可见**：与「公开」验收冲突，否决。
- **安全约束**：匿名端点必须确保不返回未披露 AI 身份（见 A3）。

## A3 未披露身份保护（最高风险）
- **候选 R1（选定）仅 eliminated 入列 + 匿名聚合计数**：公开页只列已被揭露的奖章账号；active 幸存者完全不出现，仅以「本赛季仍有 N 位神秘幸存者」聚合计数呈现（无个体标识，符合 #34 第 44 行聚合口径）。
- **候选 R2 匿名代号占位**：幸存者以 `幸存者 #hash` 进公开页，但档案页也须匿名，复杂度高且仍部分暴露「这是 AI 幸存者」语义，否决。
- **候选 R3 全部公开**：违反 #34 第 119 行，需先修订 #34 spec，否决。

## A4 触发帖语义
- **候选 R1（选定）= 自白帖**：系统已知 `ConfessionPostIds`，无外键采集成本，且自白帖即 AI「最终暴露」的官方文本。
- **候选 R2 新增外键 + 采集原始触发帖**：改动 #33 写入链路 + 指认明细保留期延长，跨 #33 边界，否决。

## A5 赛季纪念范围
- **候选 R1（选定）本期不交付 LLM 生成**：赛季概念不存在（#34 第 119 行），强行引入越界；仅交付 AIQI 趋势图读取（直接读 `arena_aiqi_results`）。
- **候选 R2 手动触发 LLM 生成**：需新建 `IArenaMemorialGenerator` + 内容安全校验 + 兜底；范围可控但非本期必交付，留作子项。
- **候选 R3 引入赛季 + 自动生成**：越界 #34 非目标，否决。

## A6 近危险时刻数据
- **候选 R1（选定）实时派生（近 3 周）**：`arena_target_tallies` 长期保留，按 `Status=="active"` 取近 ~3 周；诚实声明 `arena_accusations` 21 天清理局限。
- **候选 R2 新增持久化字段**：改 #33 写入链路采集 PostId + 延长保留，跨边界，否决。
- **候选 R3 不做**：最简，但损失档案价值，次选。
