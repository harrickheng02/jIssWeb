# 提案：图灵场积分账本、侦探技能与 AIQI 指标（#35）

## 背景与目标
#33 已实现不可变积分事件源（`arena_points_events`：成功指认 +50 / 错误指认 -5，含 `targetUserId` 但禁止外泄）。本 change 消费该事件源，把 #33 的积分桩变为真实账本与游戏经济闭环，并补齐侦探技能商店与 AIQI 实验指标。严格遵守 #33 硬约束：依赖单向 **#35 → #33**，#33 不得知晓 Accounting.Api、不得改动其已归档结算逻辑与事件契约。

## 受影响服务边界
- **Accounting.Api（主战场，当前为空壳）**：账本消费、余额/流水、月度衰减、技能购买扣费、AIQI/净流量周报跑批、只读查询 API。本 change 将其真正拉起并接入部署拓扑。
- **Model.Api（论坛域效果）**：行为扫描（读论坛词云）、公开质询（发帖 + 24h 回应标记 + agent 调度感知）。均经**共享 Mongo 库**读取 `user_skill_inventory` 校验购买状态，不反向依赖 Accounting 写。
- **Gateway / BFF**：新增 `/api/accounting/*` 路由与只读聚合。
- **前端**：个人积分面板 + 技能商店页（遵循 forum-tokens.css，8px 网格，无硬编码颜色，标题/摘要 2 行截断）。

## 范围（做什么）
1. 积分账本：消费事件 → 余额 + 只追加流水；月度 -10% 衰减（按月份幂等）；负余额下限 0。
2. 只读 API：余额查询、历史明细（响应零 `targetUserId` / `eventId`）。
3. 侦探技能商店：行为扫描(30)/免死护盾(50)/公开质询(80) 三类一次性消耗品，购买扣费、库存、效果生效；免死护盾在消费者侧 waive 误判扣分。
4. AIQI 周报：`(1 - 检测成功率) × min(本周指认 / (活跃×0.5), 1)`；样本不足标注；净流量通胀预警 / 热身包。

## 非目标（Non-goals）
- 积分充值/商业化购买；技能永久解锁。
- 修改 #33 已归档结算代码与事件契约（免死护盾通过消费者侧 waive 实现，不动 #33 写事件逻辑）。
- 赛季制框架（V1.0 后）。
