## Why

M3 治理需要一个可演示、可审计、权限边界清晰的版主/管理员帖子操作最小闭环，以支撑后续举报处理与治理能力扩展，并让前台列表与详情能一致反映治理状态。

## What Changes

- 新增帖子治理操作最小集：对帖子执行“置顶/取消置顶”并持久化。
- 新增治理操作审计：记录操作者 `sub`、目标帖子、动作与时间，并支持按帖子查询。
- 新增治理写接口的鉴权边界：仅允许具备论坛治理角色的操作者调用；版主权限需绑定到其管理版区的帖子范围。
- 扩展帖子列表与详情返回字段，使治理状态（是否置顶）可在 UI 中展示，并支持置顶排序规则。

## Capabilities

### New Capabilities

- `forum-moderation-post-ops`: 论坛帖子治理最小集（置顶/取消置顶）、权限边界与审计查询契约。

### Modified Capabilities

- `forum-content-api`: 帖子列表与详情增加置顶状态字段，并定义置顶排序规则与与现有筛选/排序的组合行为。

## Impact

- **API**：
  - 新增管理端/治理端写接口与审计查询接口（路由前缀与命名在 design/specs 中落地）。
  - 扩展 `GET /api/forum/posts` 与 `GET /api/forum/posts/{postId}` 的响应字段合同（增加置顶状态）。
- **权限**：依赖 access token 中的论坛角色声明（已由 Issue #17 定义与落地），并补齐“版主—版区”范围判断的契约与实现点。
- **数据**：帖子记录将持久化置顶状态；新增审计日志集合/表。
- **前端**：帖子列表与详情可展示置顶标记；如有治理操作台页面则仅需最小入口与按钮（可选，按任务拆分）。
