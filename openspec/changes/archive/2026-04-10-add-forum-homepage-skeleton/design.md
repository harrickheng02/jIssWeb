## Context

当前前端只有认证页、客档页、个人资料页，`/` 路由直接落到登录注册卡片，缺少论坛型产品需要的内容首屏。现阶段后端也还没有完整的论坛域接口，因此首版首页需要优先解决信息架构和路由角色，而不是追求完整数据闭环。

本次实现只动前端壳层：把首页切回内容入口，把认证体验迁移到独立路由，并用静态占位数据搭出能承接后续接口的组件结构。

## Goals / Non-Goals

**Goals:**
- 提供论坛首页最小三栏骨架，首屏可直接看到帖子、分类、热门内容和社区入口。
- 保留现有统一认证页能力，但迁移到独立路由，避免首页继续承担认证主入口角色。
- 复用现有 `auth` store，让首页能根据登录态切换发帖入口、用户区和受限交互提示。
- 组件拆分保持可扩展，后续接真实 `/api/posts`、`/api/categories`、`/api/tags/hot` 时不需要推翻结构。

**Non-Goals:**
- 不在本次接入真实论坛接口。
- 不实现帖子详情、板块页、标签页、用户主页的完整业务闭环。
- 不实现推荐算法、无限滚动、实时刷新、复杂权限和匿名机制。

## Decisions

1. **首页与认证页彻底分路由**
   - `/` 作为论坛首页，`/auth` 承载现有登录注册页。
   - 这样可以保证内容优先，同时不破坏现有认证实现。

2. **首版以单视图骨架 + 局部子组件方式落地**
   - 论坛首页先拆成 `Header`、`Sidebar`、`PostList`、`RightPanel`、`Footer` 等轻量组件。
   - 相比一次性引入复杂页面容器或全局布局系统，这样改动最小，后续替换真实数据也更直接。

3. **数据先静态建模，不先造接口封装**
   - 首页帖子、分类、热门标签、公告先用视图内或独立 mock 常量提供。
   - 这样能先把结构和交互路径跑通，避免在接口未稳定时反复改 UI。

4. **受限操作统一走认证路由**
   - 未登录用户点击发帖、点赞、评论等首版交互入口时，统一导航到 `/auth`。
   - 比在首页做复杂弹层更简单，也和现有路由守卫逻辑一致。

5. **响应式按骨架简化**
   - 桌面端三栏，平板隐藏或下沉右侧栏，手机端只保留头部和主内容流。
   - 目标是先保证可用和信息顺序，不在本次追求复杂自适应细节。

## Risks / Trade-offs

- **[风险] 静态数据与未来接口字段不一致** -> 先用接近目标接口的字段命名组织 mock，减少后续替换成本。
- **[风险] 首页改造影响现有“去登录”跳转** -> 同步把现有页面中的首页返回入口调整为认证页或真正首页，避免语义错位。
- **[风险] 新组件过早细拆导致维护成本上升** -> 只拆稳定结构组件，不提前拆筛选逻辑、分页逻辑等未成型部分。
- **[风险] 未登录点击互动缺少明确反馈** -> 首版统一用按钮文案和跳转结果表达限制，不额外引入新提示体系。

## Migration Plan

1. 新增论坛首页视图与所需子组件。
2. 将现有认证页从 `HomeView` 迁移为独立 `AuthView` 路由。
3. 更新站内返回链接，避免把“首页”等同于“登录页”。
4. 用构建和手工走查验证桌面/移动下的首页与认证页可访问性。

## Open Questions

- 帖子详情、板块页、标签页是否在下一步先做空白占位路由，还是等真实接口时再补。
- 用户信息卡里的积分、发帖数最终是否来自真实资料接口，还是论坛域单独聚合接口。
