# 设计规范（Forum / Vue3）

## 三层约束

1. **本文件** — 产品与视觉约定（色板、版式、内容规则）。
2. **`frontend/src/styles/forum-tokens.css`** — 唯一 Design Tokens 源；实现层只引用 `var(--…)`。
3. **组件** — 以 Element Plus 为基础；重复形态封装到 `components/ui`（如 `BaseButton`），再写页面。

Cursor 侧见 `.cursor/rules/forum-ui.mdc`（设计值摘要 + Vue3/EP 实现纪律）。

## 间距与圆角

- 间距刻度：`4 / 8 / 12 / 16 / 24 / 32`（px），对应 token：`--space-xs` … `--space-xl`，另有 `--space-12`（12px）。
- 圆角：`--radius-sm` 6px、`--radius-md` 8px、`--radius-lg` 12px、`--radius-pill` 胶囊。

---

## 版式

- 主容器最大宽度 **1200px**（`--container-max`）。
- 论坛三栏：左约 **240px**、中自适应（内容区约 600–720px 为佳）、右 **300px**。
- 布局优先 **flex**；避免滥用绝对定位。

---

## 论坛内容块

- 标题：**最多 2 行**，超出省略。
- 摘要：**最多 2 行**，超出省略。

---

## Element Plus

- 主操作使用 `type="primary"`。
- 全局通过 CSS 变量桥接 EP（`--el-color-primary`、`--el-border-radius-base` 等）；非必要不堆 `:deep` 覆盖。

---

## 类名

推荐使用 **BEM**：`block__element--modifier`。

## UI 设计原则

本·施耐德曼（Ben Shneiderman）提出的**界面设计八大黄金法则**适用于论坛与管理端交互；新功能与改版应对照检查，并与 Element Plus 的反馈、确认、表单校验、撤销等能力对齐。

### 1. 力求一致性

设计类似功能和操作时，统一图标、颜色、菜单结构等，减少用户认知负担，帮助用户快速熟悉界面。

### 2. 允许频繁使用快捷键

为熟练用户提供快捷操作方式（如键盘快捷键），提升操作效率。

### 3. 提供明确的反馈

用户每完成一个操作，系统都要在合理时间内给出反馈（如视觉高亮、Toast、加载态），让用户感知操作结果。

### 4. 设计对话，告诉用户任务已完成

明确告知用户操作流程的结束状态（如提交成功页、完成提示与后续指引），让用户获得明确的完成感。

### 5. 提供错误预防和简单的纠错功能

从设计上减少用户出错可能（约束输入、确认危险操作）；若出现错误，给出清晰易懂的解决方案，避免仅展示错误代码或晦涩文案。

### 6. 应该方便用户取消某个操作

提供明显的撤销、取消或回退方式，让用户能恢复之前的步骤，降低操作失误的焦虑感。

### 7. 用户应掌握控制权

让用户主动主导操作流程，按用户预期设计交互逻辑（可跳过、可延后、非强制打断），建立对界面的信任感。

### 8. 减轻用户记忆负担

界面设计要简洁，利用**再认**而非**回忆**：通过选项列表、默认值、上下文提示让用户选择或确认，避免要求用户凭记忆输入冗长或易错信息。
